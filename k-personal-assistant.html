02 / Working features

Built around everyday use.

01

School & schedule

Read-only Apple Calendar snapshots and a Blackboard calendar feed support schedule and assignment views. Incorrect deadlines can be dismissed locally without changing the source.

02

Reminders that reach my phone

A paired Telegram bot delivers reminders, with acknowledgement and snooze controls, quiet hours and no replay of missed notifications after sleep.

03

Routines & small milestones

Daily study goals, gym/rest-day check-ins and weekly project milestones help make progress visible. Optional health logs do not prescribe supplement doses.

04

Internship discovery

Selected public employer feeds populate a local board with original listing links, review notes and application statuses. Coverage is limited; eligibility and each application need review.

03 / How it fits together

Private by design.

React dashboard→FastAPI on my Mac→Local SQLite records

Private phone access uses Tailscale. A separate Telegram connection handles configured notifications. Credentials stay outside source control, and the public portfolio contains only this project description. The local AI adapter has no cloud-model fallback.

For public job data, K uses selected published employer feeds documented by Lever’s Postings API.

04 / My role & what I learned

Learning through a real workflow.

I defined the workflow, chose priorities and privacy boundaries, tested the setup and refined the interface. Implementation was developed with substantial AI coding assistance. I am learning how the frontend, backend, database and notification delivery work together; this project is not a claim that I independently wrote every component.

Useful lessons so far: storing a reminder is different from delivering it; an integration can be configured without being connected; and a simple phone interface needs clear priorities rather than every feature on the first screen.

The current implementation passes 37 automated tests covering core access controls and feature behavior. The frontend production build also succeeds. These checks do not replace real-device testing.

05 / Honest project status

Working, with more to learn.

  • Local chat controls and a question queue are implemented. Ollama/model installation is deferred, so AI answers are not active yet.
  • Voice controls include Mac text-to-speech and an on-device browser dictation capability check. Always-listening wake words are not enabled.
  • School Outlook access awaits administrator approval. Gmail is not connected.
  • The assistant requires my Mac and its server to be awake. Unattended application submission is not implemented.

Next steps: test the mobile experience further, connect a local model when ready and improve the application-review workflow.
